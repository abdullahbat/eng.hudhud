# توثيق صيغة بيانات مشروع «هدهد الهندسة» (`docs/data-format.md`)

يعتمد موقع **هدهد الهندسة** على ملفين بصيغة JSON محفوظين داخل مجلد `data/` لتمثيل خرائط الكلية وشبكة الممرات والمرافق والدكاترة والمعالم:
1. **`data/campus.json`**: البيانات الكاملة للأدوار، النقاط، الممرات، المرافق، المعالم، والدكاترة.
2. **`data/settings.json`**: إعدادات نظام رموز القاعات، كلفة الدرج والمصعد، ورابط الإبلاغ عن خطأ.

صُممت هذه الصيغة بحيث تكون مسطّحة وواضحة وسهلة التعديل برمجياً أو من خلال **صفحة الإدارة (`admin.html`)** في المرحلة 6 دون الحاجة لأي خبرة برمجية.

---

## أولاً: القواعد العامة وعلامة النسخة التجريبية (`demo`)

- يحمل كل عنصر تجريبي في القوائم الست (`floors`, `nodes`, `edges`, `facilities`, `landmarks`, `doctors`) الخاصية `"demo": true`.
- طالما وُجد عنصر واحد على الأقل يحمل `"demo": true`، يظهر في أعلى الموقع شريط: **«نسخة تجريبية: البيانات ليست حقيقية»**.
- عند الضغط على زر «إزالة البيانات التجريبية» في صفحة الإدارة (المرحلة 6 و7)، تُحذف جميع العناصر التي تحمل `"demo": true`.

---

## ثانياً: هيكل ملف `data/campus.json`

### 1. الأدوار (`floors`)
قائمة بجميع أدوار الكلية مرتبة تصاعدياً حسب `order`:

```json
{
  "id": "ground",
  "name": "الدور الأرضي",
  "order": 0,
  "mapImage": "maps/floor-ground.webp",
  "width": 1000,
  "height": 700,
  "attribution": "© خريطة تجريبية — هدهد الهندسة",
  "scale": {
    "p1": { "x": 150, "y": 250 },
    "p2": { "x": 850, "y": 250 },
    "distanceMeters": 70
  },
  "demo": true
}
```

- **`id`**: معرّف فريد للدور (مثل `ground`, `first`, `second`).
- **`name`**: الاسم المعروض بالعربية (مثل `الدور الأرضي`، `الدور الأول`).
- **`order`**: رقم ترتيب الدور (`0` للأرضي، `1` للأول، `2` للثاني، ويمكن استخدام `-1` للقبو).
- **`mapImage`**: مسار صورة الخريطة بصيغة WebP داخل `public/maps/`.
- **`width` و`height`**: أبعاد صورة الخريطة بالبكسل.
- **`attribution`**: نص النسبة لمصدر الصورة إن وُجد (مثل `© Google` للدور الأرضي إذا استُخدمت صورة قمر صناعي).
- **`scale` (مقياس الرسم)**: يُحدّد بنقطتين `p1` و`p2` بالبكسل على صورة الدور، والمسافة الحقيقية بينهما بالأمتار (`distanceMeters`). منه يُحسب معامل التحويل:
  $$\text{metersPerPixel} = \frac{\text{distanceMeters}}{\sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}}$$

---

### 2. النقاط (`nodes`)
تمثّل تقاطعات الممرات، وأبواب القاعات والمرافق، ومواقع الدرج والمصاعد والمداخل على صورة الدور:

```json
{
  "id": "g-n1",
  "floorId": "ground",
  "x": 150,
  "y": 250,
  "kind": "junction",
  "demo": true
}
```

- **`id`**: معرّف فريد للنقطة.
- **`floorId`**: معرّف الدور الذي تقع فيه النقطة.
- **`x` و`y`**: إحداثيات النقطة بالبكسل على صورة الخريطة (محور `x` يتجه لليمين، ومحور `y` يتجه للأسفل).
- **`kind`**: نوع النقطة التوضيحي (`junction` تقاطع ممر، `door` باب مرفق، `stairs` درج، `elevator` مصعد، `entrance` مدخل).

---

### 3. الوصلات / الممرات (`edges`)
تمثّل الممرات الواصلة بين نقطتين في نفس الدور:

```json
{
  "id": "g-e1",
  "floorId": "ground",
  "from": "g-n1",
  "to": "g-n2",
  "computedLengthMeters": 10,
  "manualLengthMeters": 10.5,
  "demo": true
}
```

- **`from` و`to`**: معرّفا النقطتين الطرفيتين للممر (الممرات ثنائية الاتجاه).
- **`computedLengthMeters`**: الطول المحسوب تلقائياً من المسافة بالبكسل على الصورة مضروبة في مقياس الدور (`scale`).
- **`manualLengthMeters`** *(اختياري)*: الطول المقاس يدوياً على أرض الواقع بالمتر. إذا وُجد، يتقدّم على الطول المحسوب في حساب المسارات، بشرط ألا يختلف عن الطول المحسوب بأكثر من **20%** (وإلا يرفضه سكربت التحقق لتنبيه المدخل إلى وجود خطأ في القياس أو المقياس).

---

### 4. المرافق (`facilities`)
تشمل القاعات الدراسية، مكاتب الدكاترة، المصليات، دورات المياه، الدرج، المصاعد، والمداخل:

```json
{
  "code": "G-01",
  "type": "room",
  "name": "قاعة دراسية G-01",
  "floorId": "ground",
  "nodeId": "g-n2",
  "connectorGroup": null,
  "demo": true
}
```

- **`code`**: رمز المرفق الفريد (مثل `G-01` لقاعة، أو `STAIR-EAST-G` لنقطة درج في دور معين).
- **`type`**: نوع المرفق، ويكون أحد القيم الثابتة التالية:
  - `room` (قاعة دراسية / معمل)
  - `office` (مكتب عضو هيئة تدريس أو إداري)
  - `prayer` (مصلى)
  - `wc_men` (حمام رجال)
  - `wc_women` (حمام نساء)
  - `stairs` (درج)
  - `elevator` (مصعد)
  - `entrance` (مدخل)
  - `other` (أخرى: كافيتريا، تصوير، استراحة...)
- **`name`**: الاسم المعروض للطالب بالعربية.
- **`floorId`**: الدور الذي يقع فيه المرفق.
- **`nodeId`**: النقطة (`node`) الواقعة عند باب المرفق على شبكة الممرات.
- **`connectorGroup`** *(للدرج والمصاعد فقط)*: الاسم الثابت المشترك الذي يربط الدرج أو المصعد عبر الأدوار المختلفة (مثل `"درج-شرق"`، `"درج-غرب"`، `"مصعد-1"`). يجب أن يظهر كل اسم مشترك في دورين على الأقل ليتمكن الطالب من الانتقال بين الأدوار عبره.

---

### 5. المعالم (`landmarks`)
أماكن بارزة داخل الكلية يعرفها الطلاب بسهولة وتُستخدم لتحديد موقع الطالب أو لإثراء الشرح الكتابي عند الانعطافات («انعطف يساراً عند المصلى»):

```json
{
  "id": "lm-main-gate",
  "name": "البوابة الرئيسية (بهو العمادة)",
  "floorId": "ground",
  "nodeId": "g-entrance-main",
  "demo": true
}
```

---

### 6. الدكاترة (`doctors`)
قائمة أعضاء هيئة التدريس وتقتصر حفاظاً على الخصوصية على الاسم ورمز المكتب فقط:

```json
{
  "id": "doc-1",
  "name": "د. تجريبي أحمد المنصور",
  "officeCode": "F1-09",
  "demo": true
}
```

- **`name`**: اسم عضو هيئة التدريس.
- **`officeCode`**: رمز المرفق (`facility.code`) الذي يمثّل مكتبه، ويجب أن يكون موجوداً في قائمة `facilities`.

---

## ثالثاً: ملف الإعدادات ونظام رموز القاعات (`data/settings.json`)

```json
{
  "roomCodeSystem": {
    "enabled": true,
    "pattern": "^(G|F1|F2)-(\\d{2})$",
    "description": "نظام تجريبي: بادئة الدور (G للأرضي، F1 للأول، F2 للثاني) متبوعة بشرطة ورقم القاعة من خانتين",
    "floorPrefixMap": {
      "G": "ground",
      "F1": "first",
      "F2": "second"
    }
  },
  "routingCosts": {
    "stairsMetersPerFloor": 15,
    "elevatorMetersPerWait": 25
  },
  "reportIssueUrl": ""
}
```

- **`roomCodeSystem`**: يسمح باستنتاج الدور من رمز القاعة والتحقق من عدم إدخال قاعة في دور خاطئ. في المرحلة 7 يُضبط النمط (`pattern`) و`floorPrefixMap` على نظام الكلية الحقيقي.
- **`routingCosts`**: كلفة مقارنة افتراضية لاختيار أفضل درج أو مصعد (لا تُضاف إلى المسافة المترية المعروضة للطالب).
- **`reportIssueUrl`**: رابط نموذج البلاغات (إذا تُرك فارغاً لا يظهر زر «أبلغ عن خطأ»).
